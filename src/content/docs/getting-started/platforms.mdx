Lunchpad runs on Windows, macOS and Linux. Almost everything works the same on all three. The exceptions are features that reach into other programs (pressing keys in them, moving the mouse, moving their windows), because each system decides how much one program may do to another.

On Linux it also matters which display server your desktop runs on:

- **X11** (also called Xorg) lets programs send keys and mouse input to each other, like Windows and macOS do.
- **Wayland**, the default on current GNOME, KDE Plasma and most new distributions, does not. Programs there cannot type into, click into or move each other, and only the desktop decides which window stays on top.

Lunchpad checks this when it starts. **Settings → Diagnostics** names the session, for example `wayland session`, and lists what is not available.

1. The output device list shows the names ALSA uses: `default`, `pipewire` or `pulse`, and the sound cards. `default` follows the device chosen in your sound settings.
2. Through Speech Dispatcher, which most desktop distributions install. The voices are the ones it offers.
3. Through `pactl`, which PulseAudio and PipeWire (with `pipewire-pulse`) both provide. Devices are listed by the names your sound settings show.
4. Needs the Accessibility permission: **System Settings → Privacy & Security → Accessibility**. See [Installation](/getting-started/installation/).
5. The tray needs a desktop that shows tray icons (StatusNotifier / AppIndicator). KDE Plasma, Xfce, Cinnamon and most others do; on GNOME install the *AppIndicator and KStatusNotifierItem Support* extension.
6. Through the Secret Service, which GNOME Keyring and KWallet provide. It has to be unlocked, which a desktop login usually does.

## What Lunchpad does about a missing feature

You do not have to keep track of the table yourself:

- **The "Add action" menu leaves out actions this system cannot run.** Under Wayland the **Keyboard & mouse** and **Window** groups are gone and **Flow** has no push-to-talk; on Linux with X11 only the **Window** group is gone.
- **Actions that came with a profile from another computer stay where they are**, faded. Hovering one says why it does nothing here. They keep their settings, so the profile still works when you take it back to Windows or macOS, and the rest of the macro runs as usual.
- **Settings that would have no effect are greyed out**: **Keep the window above other windows** under Wayland, and the push-to-talk key under **Settings → Keyboard & mouse**, which then says why. The tray menu has no **Stay on top** entry under Wayland.

<Aside type="tip" title="On Linux and need hotkeys?">
Log in to an X11 session if your desktop still offers one: pick it on the login screen, for example **Plasma (X11)**, or use a desktop that runs on X11 such as Xfce, Cinnamon or MATE. Recent GNOME releases have no X11 session any more. Programs running under XWayland inside a Wayland session do not count: Lunchpad looks at the session, not at how one program draws its window.
</Aside>
