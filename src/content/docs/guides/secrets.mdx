Macros often need a key: a token for a web API, the password of a smart-home bridge, an API key for a voice service. Typing it into an [HTTP request](/actions/system/http-request/) works, but then it sits in your profile — and a profile is what you export, back up and send to a friend.

**Secrets** keep those values somewhere else. You give a value a name once, and your macros use the name.

<AppShot name="settings-secrets" alt="The Secrets settings tab: a Name and a masked Value field with an Add button, and a list of two secrets, each showing the placeholder to use and a Replace button." />

## Where they are kept

In your operating system's credential store: the **Keychain** on macOS, the **Credential Manager** on Windows, the Secret Service on Linux. Lunchpad's settings file holds only the *names*, and the profile holds nothing at all.

A value is never shown again once saved, not in the app and not in the diagnostics report.

## Add a secret

<Steps>

1. Open **Settings → Secrets**.

2. Type a **Name**: letters, digits, `_` and `-`, up to 64 characters. This is what you write in your macros, so keep it short — `twitch`, `hue_bridge`, `elevenlabs`.

3. Paste the **Value** and click **Add**.

</Steps>

Adding a name that already exists replaces its value. **Replace** on a row does the same for that one, and the **✕** deletes it.

## Use one in a macro

Write `{{secret.` and the name, for example `{{secret.twitch}}`. The row in the settings shows the exact placeholder to copy. In any text field of an action, typing `{{` offers your secrets along with the variables.

Secrets work everywhere Lunchpad fills in values, which is every field that takes a `{{placeholder}}`:

- an [HTTP request](/actions/system/http-request/): the address, header values, the body, the bearer token, the user name and password of a login, and file paths,
- the text of [Text to speech](/actions/media/text-to-speech/), the arguments of [Launch application](/actions/system/launch-application/), typed text in a [Hotkey sequence](/actions/input/hotkey-sequence/),
- the entity, service and data of the [Home Assistant](/guides/home-assistant/) actions, and the scene, source and filter names of the OBS and Streamlabs actions.

<Aside type="tip">
A header with the value `{{secret.elevenlabs}}` is the normal way to call a paid API from a pad. **Send test** in the HTTP editor resolves secrets, so the test hits the real service with the real key.
</Aside>

## What secrets are not

- **They are not variables.** They never appear in **Settings → Variables**, a [script](/actions/system/run-script/) cannot read them through `vars` or `globals`, and nothing writes them to disk outside the credential store.
- **They are not shown in descriptions.** `{{secret.…}}` in a [button description](/guides/buttons/#description) stays as written.
- **They are not logged.** The log names the address as you typed it, so a key in a query string does not end up in a log file.

Deleting a secret leaves the text `{{secret.name}}` in your actions; they then send it literally, so clean the actions up as well.

## Sharing and backups

A secret never leaves your computer, so a page you [share](/guides/pages-and-backup/#share-on-the-community-hub) or back up carries only the `{{secret.name}}` reference. Whoever installs it needs a secret of that name of their own.

That is exactly why a key belongs in a secret rather than in the action. A password typed straight into an HTTP request is part of the button: share that button, and the password goes with it.

## A page from someone else

A secret is filled in by name, from the credential store of whoever presses the pad. So a page made by someone else can name a secret **you** have — and send its value wherever that action points, without ever having seen the value.

Lunchpad shows you any such action before a page is imported, under **Needs a close look**, together with the destination it would go to. See [Check before importing](/guides/pages-and-backup/#check-before-importing).

<Aside type="caution">
A secret protects your profile, not your computer. Anyone who can use your unlocked account can run the macros that use the key.
</Aside>
